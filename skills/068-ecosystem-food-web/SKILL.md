# 068 生态系统与食物网

课程来源：https://app.notion.com/p/41f938852e8c81249e4dd567dcefdb1b
课程页面：https://tanghuaizhe.github.io/mental-models-audit/course/068-ecosystem-food-web/

## 何时调用

**trigger**：开发者、商户、用户、内容方或供应商等多类角色相互依赖；关键节点变化可能产生跨角色的级联影响。

**anti_trigger**：只是单一用户群扩大、内部成本摊薄，或列出合作伙伴却没有互补关系与依赖证据。单位成本交给 046；参与者增加直接提升其他参与者价值交给 047。若本模型不会改变判断或证据优先级，标记为 `Not material`。

## 审查问题

1. 产业链哪些节点是关键种/瓶颈？
2. 一个节点消失会如何级联？
3. 替代路径和缓冲库存在哪里？
4. 什么证据会让你降低或推翻当前判断？
5. 有没有其他模型能同样解释这些证据，导致当前机制并非唯一解释？

## 证据要求

- 优先引用公司、交易所、监管原始披露，可靠结构化财务数据、行业一手数据或可复核事实。
- 区分：已披露事实 / 外部证据 / 分析判断 / 前瞻假设。
- 不允许用模型名称本身充当证据。
- 关键事实缺失时写入 `unknowns`，不要补故事。

## 执行步骤

1. 给出相关性：`Material | Secondary | Not material`。
2. 写出本模型试图回答的唯一核心问题。
3. 分列支持与反对证据，并注明来源/期间。
4. 明确底层机制，而不是只做类比。
5. 说明对收入、利润率、ROIC、竞争位置、资本需求、尾部风险或估值中的哪一项产生影响。
6. 给出最强反例或边界条件。
7. 写出至少一个可观察的证伪条件。
8. 给出 0–100 的置信度。
9. 推荐 0–3 个下一模型；若只是重复机制则不推荐。

## 输出

严格遵循 `../../schema/audit-output.yaml`。若为 `Not material`，只输出 model、relevance、reason，可省略其余字段。

## 边界

这个模型是地图，不是结论。不要把跨学科类比当成公司事实；不要因模型“听起来适用”就提高 thesis 权重。任何前瞻判断必须回到可观察证据和明确时间尺度。
